本书主要介绍了UNIX（POSIX.1, SUS 等）的系统函数，穿插讲解了这些系统函数为什么要这样设计，有些会给出实现代码。
UNIX 如今已经不是任何一个具体的操作系统了。他变成一个商标，由The Open Group持有^[https://www.opengroup.org/] 。
UNIX 标准化为了让应用程序在不同的操作系统之间方便的移植：
**单一 UNIX 规范（Single UNIX Specification）**：规定了操作系统必须提供哪些系统接口、命令、工具和联网服务。
**POSIX** 标准：侧重于可移植操作系统接口本身。
一个操作系统实现UNIX的规范，并取得 The Open Group 的认证，就可以称为Unix 系统，例如Mac OS。也有一些操作系统会兼容UNIX 规范，但没有商标（没有认证，或者接口不完全一致），例如FreeBSD、Linux。
可以看到这本UNIX与C的关系非常密切，这也是C一直经久不衰的原因之一

# UNIX 系统
## 限制（2.5）
UNIX 实现中有很多不同的限制，如文件名最大长度、进程可以打开的文件数量、最大进程数等等。标准没有把这些限制统一，原因是：1. 早期UNIX 变体较多，无法完全兼容。2. 很多限制跟硬件相关，强行限制反而不好。
因此在编写可移植的程序的时候需要考虑这些限制。通常：
1. 在编译时，头文件的宏中定义
2. 对于文件或目录**无关**的，调用 sysconf 函数判断
3. 对于文件或目录**有关**的，调用pathconf, fpathconf函数判断

### 系统文件和信息
UNIX 中有很多系统自己的文件，例如 shadow 文件（存储密码，只有少数程序需要访问）
UNIX 的数据文件通常要有三个函数：
- get 函数：读取一条记录
- set 函数：打开文件、倒回文件（到开头）
- end 函数：关闭文件

# 文件与IO
## 文件IO
UNIX shell 三个默认文件描述符：
- 0 标准输入
- 1 标准输出
- 2 标准错误输出

**工作目录**：同一进程内的所有线程共享当前的工作目录
**空洞文件**：通过 lseek 调整文件偏移量时，偏移量可以大于当前文件的长度，此时文件出现空洞，空洞内都是0，但是不占用磁盘空间。（但是一些操作，例如读取文件再写入到一个新文件中，空洞就会被真实的0填充，此时就会占用空间）
**预读**：操作系统一般采用预读策略，检测到应用程序正在进行顺序读取时，会多读取比要求更多的数据

### 原子操作
pread 相当于先调用lseek，再调用 read。pwrite 类似：
- 调用 pread 时，无法中断其定位和读取操作
- 调用 pread 时，当前文件偏移量不更新
### sync
我们向文件写入数据时，内核先将数据复制到缓冲区，随后数据进入队列，最后写入文件。
sync 将所有修改过的块缓冲区排入队列，然后返回，他不等待实际的写磁盘完成
### ioctl
ioctl 是文件操作的IO操作的杂货箱，在驱动程序中用的比较多

- i 结点包含了与文件有关的所有信息：文件类型、文件访问权限位、文件长度、指向文件数据块的指针。stat 函数的大多数信息是从i 节点获取中的。不过，文件名跟i 结点号存储在目录项中

### 链接 link
很多操作系统不允许出现指向目录的硬连接（或者只有root 权限才行），目的是避免循环
**ulink**
- 每个文件都有链接的计数。当关闭文件时，内核检查打开该文件的进程数，如果为0，内核再检查文件的链接数，如果也为0，则删除文件。
- 利用上面ulink的特性，进程中的临时文件可以创建后马上调用ulink。这样进程结束（崩溃），临时文件就会自动删除
- ulink 权限，必须要对包含该文件的目录有读写和执行权限，同时还要满足下列三个条件之一：
	- 拥有该文件
	- 拥有该目录
	- 具有超级用户权限

## 高级IO
### 非阻塞IO
普通IO在访问低速设备时可能会阻塞，非阻塞IO避免了这些问题：
- 读低速设备，但数据还没准备好（网络）
- 写低速设备，还没准备好接收（网络阻塞）
- 打开低速设备（等待连接）

非阻塞IO在不能完成操作时会出错并立即返回
### 记录锁
对文件按字节长度加锁，锁住某一部分，主要用于数据库系统。也叫 byte-rang locking
### IO 多路复用
select 
- 传入：关心那些描述符；对于这些描述符，关心那些条件；愿意等待多久
- 内核返回：就绪描述符的数量；对于读、写、异常 三个条件有哪些描述符就绪
poll: 与select 函数类似，但是他们的编程接口不同
### 异步IO
使用POSIX 异步IO 接口时，有以下新增的复杂性：
- 对每个异步操作，都会有三个可能产生错误的地方：1. 提交操作相关 2. 操作本身结果 3. 异步操作的状态函数
- 引入大量设置项和处理规则
- 从错误中恢复十分困难

异步IO 采用AIO 控制块，其中 aio_buf 作为缓冲区。读操作时，会把数据复制到 aio_buf，写操作，则将数据从缓冲区复制出来。
执行异步IO操作时我们必须显式地指定文件偏移量
不要在同一个进程中把异步IO函数和传统IO函数针对同一个文件混用在一起

**aio_read，aio_write** 这些函数返回成功（返回值与真实异步IO操作的结果没有任何关系），则异步IO请求被系统放入等待处理队列中，此时要保证AIO的缓冲区稳定，在IO操作完成前不能在此执行这些函数。需要使用 **aio_error** 函数获取异步操作结果（成功、失败、等待等）、以及返回值

**aio_suspend**: 阻塞进程，直到操作完成
**aio_cancel**: 取消操作，不保证系统可以取消正在处理中的异步IO操作。
### readv 和 writev 函数
散布读、聚集写
readv 将数据按照顺序散布到数组中
writev 将缓冲区数据按顺序缓冲区聚集在一起

### readn 和 writen 函数
管道、FIFO、终端网络等设备可能出现:
1. 请求读取 n 字节，实际收到少于n 个数据
2. 一次写入n字节，实际写入少于 n (缓冲区满)
readn writen 内部多次调用 read 或者 write直到满足N需求

### 内存映射IO
内存映射IO 允许将一个磁盘文件映射到内存的一块缓冲区
内存映射区域可以通过fork函数产生的子进程继承，通过exec函数启动的进程无法继承内存映射区域
msync 用来主动将修改写回磁盘
当进程终止时，内存映射区域会自动解除。也可以调用munmap函数来主动解除内存映射区域。关闭内存映射区域的文件描述符，并不会解除内存映射区域
read write 方法相对于mmap 和memcpy方法的主要区别是，read write 会做很多复制工作

# 进程
## 进程环境
### main 函数
内核执行C程序之前，会在main 函数之前调用一个启动例程，可执行文件将启动例程作为程序的启始地址，这一操作由链接器设置，链接器由编译器触发。启动例程从内核获取命令行参数和环境变量，随后调用main 函数。
main 函数返回，exit 函数自动调用。启动例程如下：
```C
exit(main(argc, argv))
```
### 进程终止
8种终止方式（前5种正常退出，后3种异常退出）：
1. main 返回
2. 调用exit函数：执行特定清理再返回内核
3. 调用_exit 或_Exit函数：立即返回内核
4. 从最后一个线程启动例程返回
5. 从最后一个线程调用 pthread_exit 函数
6. 调用abort函数
7. 接收一个信号
8. 最后一个线程对取消请求做出响应

退出状态：
- main函数隐式返回（不执行return），退出状态为0
- 未定义的退出状态
	1. 调用三个 exit 函数未指定退出状态
	2. main 函数调用return，但是没指定返回值
	3. main 函数的定义没有指定返回值为 int

**atexit 函数** 用于注册 exit 函数自动调用的函数（exit handler），ISO C 规定最少可以注册32个函数。
- 注册的函数以函数指针形式传入，参数类型跟返回值均为 void。
- 这些函数调用的顺序与注册的顺序相反（栈结构）
如下图所示，内核执行一个程序的**唯一**方法是调用exec，进程**自愿**终止的唯一方式是显示或隐式调用_exit 或_Exit 函数

### 命令行参数与环境变量
ISO C 跟POSIX 规定 `argv[argc]`为空指针，因此下面的写法是合法的：
```C
for(i=0; argv[i] != NULL; i++)
```

访问特定环境变量通常使用 `getevn` 和 `putenv` 函数
### C 程序的内存布局
一个C程序由以下几部分组成：
- 正文段：CPU 执行的机器指令，正文段通常可共享
- 初始化的数据段：也叫数据段，包含程序中已经显示初始化的变量
- 未初始化的数据段：也叫bss 段（名称来源于早期汇编操作符“block start by synbol”），这部分的数据回被内核在程序执行前初始化为0或空指针
- 栈：每次递归函数调用自身，就使用一个新的栈帧
- 堆

上面5部分只有 **正文段跟初始化数据段** 回保存到程序文件中
程序文件中还会有：符号表、调试信息、作用域动态共享库的链接表等，这些不会装载到程序的映像中。

### 内存申请
ISO C 的三个内存申请函数：
- malloc，不初始化
- calloc，申请到的内存的每个比特都会初始化为0
- realloc，增加或缩小之前申请的内存区域。可能回移动内存（指针数值变化），新增区域的初始值不确定。

sbrk 系统调用：可以扩大或缩小进程的存储空间。但大多数malloc 和 free 的实现都不缩小进程的存储空间。释放的空间会保留为进程空间以备稍后再次被分配，这些空间保存在malloc 池中，不会返回给内核。
大多数实现分配的内存比请求的稍大一些，额外的空间用来记录管理信息：如块长度、指向下一个块的指针等。

其他内存函数：
alloca：在栈上分配内存

## 进程控制
### 进程标识符（PID）
每个进程用一个非负整数作为独一无二的进程ID。进程ID会被复用，UNIX 采用延迟复用算法，这样防止一个新进程被误认为是使用相同ID的某个已终止的进程
**特殊进行**
- 0：调度进程（swapper），他是内核的一部分，运行在内核态
- 1：init 进程，由内核在引导过程结束时调用。用不消亡，以超级用户权限运行在用户态，是所有孤儿进程的父进程
- 2：页守护进程（pagedaemon）,负责虚拟内存系统的分页机制
### fork 函数
fork 函数用于创建子进程，fork 函数调用一次，返回两次：
1. 子进程返回 0
2. 父进程返回 子进程的 PID，父进程创建多个子进程时，有PID可以区分（没有其他函数可以获取某个字函数的PID）

子进程跟父进程继续执行fork函数之后的命令，这里的代码一般这样的：
```C
pid_t pid;
if((pid=fork()) < 0){
	// error
} else if(pid == 0){
	// 子进程
} else {
	// 父进程
}
```

子进程获得父进程的数据段、堆、栈的副本（写时复制），此外还有很多，可以参考原书
**文件共享**：子进程跟父进程共享相同的文件描述符、**文件偏移量**，参考下图
![[attachments/Pasted image 20261115182616.png]]

**fork失败**：
1. 系统中有太多进程了
2. 某个用户的进程数量超过系统限制，该用户不能再创建

**fork 用途**：
1. 进程希望复制自己，让父子进程执行不同的代码，常见于网络服务器
2. 进程想要执行不同的程序，如shell

**vfork**：不可移植，不应该使用
### exit 函数
- 无论进程如何终止，最终都会执行内核中相同的代码段
- 父进程可以通过 wait 或 waitpid 函数获取字函数的终止状态。内核中保留。
- 父进程先于子进程终止，init 进程会成为子进程的父进程
- 已经终止但其父进程尚未等待它（尚未调用wait函数）的进程被称为僵尸进程
- init 的子进程终止时，init 都会调用一个wait 函数获取其终止状态
### wait waitpid
调用这两个函数会：
- 阻塞（子进程都在运行）
- 立即携带子进程的终止状态返回（某个子进程已经终止）
- 立即返回错误（没有子进程）
### exec
基本进程控制原语：
- fork 创建新进程
- exec 启动新的程序
- exit 终止程序
- wait 等待程序终止

不要在搜素目录中包含当前目录，安全原因，参考下面例子：
*   **场景**：攻击者在共享目录（如 `/tmp`）里放一个恶意脚本，命名为 `ls`。
*   **陷阱**：你或管理员进入该目录并输入 `ls`。如果 `.` 在 `PATH` 里，系统会执行这个恶意脚本，而不是真正的 `/bin/ls`。
*   **后果**：脚本可以在后台执行任意破坏（如删除文件、窃取信息），而你看到的可能只是正常 `ls` 的输出，难以察觉。这对 **root 用户**尤其危险，因为恶意脚本会以最高权限运行。

## 信号
**信号三种动作**：
1. 忽略，大多数信号能够忽略。SIGKILL、SIGSTOP 不可忽略，确保内核、超级用户能够停止任何进程
2. 捕捉此信号，信号发生时调用某个函数。SIGKILL、SIGSTOP 不可捕捉
3. 执行系统默认动作，通常是终止进程，或者忽略
### 信号函数
kill 命令、kill函数 知识向一个进程或者进程组发送一个信号
exec 函数将任何需要捕获的信号的处理方式调整为其默认动作
shell 会自动将后台进程对中断、退出信号的处理方式设置为忽略。避免输入中断字符影响到后台进程
fork函数创建的子进程会继承父进程的信号配置
### 可重入函数
在信号处理程序中可以安全调用的函数，这些函数是可重入的（异步信号安全函数），通常不可重入函数包含以下：
- 使用静态数据结构
- 调用malloc或者free
- 是标准IO库的一部分
### 可靠信号的术语和语义
在信号产生和传递之间的这段时间，称为信号为挂起信号（未决信号）
进程可以选择阻塞信号的传递
进程解除阻塞信号之前入过产生多次信号，内核只会传递一次信号
与进程当前状态相关的信号应该优先于其他信号传递（例如SIGSEGV）
每个进程都有一个信号掩码，定义了当前被阻止传递给当前进程的信号集
### kill raise
- kill 函数项一个进程或者进程组发送信号
- raise 允许进程给自己发信号

alarm 函数用于设置定时器，每个进程只能有一个闹钟。
pause 函数用于挂起调用进程，直到捕获信号

## 进程间通信
### 管道
进程先调用pipe函数，然后调用fork函数两创建一个父进程与子进程通信的IPC通道
多个进程同时向一个管道（或FIFO）写，写入的字节太多，则当前进程的数据可能与其他进程的数据交叉

popen 函数特别适用的场景是作为一个简单的过滤器，来转换命令的输入和输出
### 协同进程
当一个过滤器既产生某个过滤器的输入，又读取其他过滤器的输出时，他就变成了协同进程
协同进程通常运行在shell后台，且它的标准输入和标准输出连接着其他管道的程序
### FIFO（命名管道）
未命名管道只能用于两个关联的进程之间，且两个进程由一个共同的祖先来创建。
FIFO 没有关联的进程之间也可以交换数据
正常的IO处理函数（close read write unlink）对FIFO文件都有效
### 消息队列
本质是存储在内核中的消息链表
每一条消息都由一个正的长整型类型字段、一个非负长度字段、实际数据组成。消息总是放到队列的末尾
消息队列不一定要先进先出
### 信号量
信号量是一个计数器
为了获取共享资源，进程需要执行以下步骤：
1. 测试信号量
2. 信号量为正，进程获得共享资源，线号量-1
3. 否则信号量为0，进程将进入睡眠状态，知道信号量的值大于0
测试信号量的值以及-1操作必须是原子操作
### 共享内存
最快速的IPC技术
通常需要搭配信号量来保证共享区域的同步访问
共享内存与文件的内存映射不同，不会关联任何文件


# 线程
## 线程
进程中的一切都可以在进程中的线程之间共享
**线程标识**：使用结构体 pthread_t 表示
### 线程终止
三种退出方式：
1. 线程从启动用例返回，返回值就是退出码
2. 线程可以被同一进程中的另一个线程取消
3. 调用 pthread_exit 函数

**pthread_join** ：调用 pthread_join 函数，会自动将要链接的线程置于分离状态，以便可以回收其资源
传递给pthread_create pthread_exit 的指针可以用于传递的信息，但必须保证指针指向的内存有效
**pthread_cancel**: 
取消线程，它不等待线程的终止，仅仅发出请求而已。
被取消的线程可以通过atexit 函数注册线程清理函数。如果线程从启动用例的调用返回而终止，则不会调用这些清理函数。清理函数的调用跟安装顺序相反（栈）
**pthread_detach**:
分离线程，被分离的线程的潜在存储资源在终止时被立即回收。线程分离后不可以调用join 函数等待其终止状态（为定义行为）。
### 线程同步
**互斥量**
pthread_mutex_trylock， 有条件的锁定互斥量：
1. 若互斥量已经解锁，则加锁并返回0
2. 否则，加锁失败，不阻塞，返回 `EBUSY`

pthread_mutex_timelock，限制阻塞的时间，超时参数是愿意等待的绝对时间

**读写锁（共享独占锁）**
一次只有一个线程在写模式下持有读写锁，但多个线程可以同时在读模式下持有读写锁。
写锁定时，所有试图锁定他的线程都会被阻塞，直到写锁解锁。
读锁定时，说有试图以读模式锁定的都可以获得锁；但是任何以写模式加锁的线程都会被阻塞，直到所有线程释放读锁。
带有超时的读写锁

**条件变量**
条件变量与互斥量一起使用时，条件变量允许线程以无竞争的方式等待任意条件的发生
条件变量本身受互斥量保护的。线程必须先锁定互斥量才能改变条件状态。传递给`pthread_cond_wait`函数的互斥量保护条件
`pthread_cond_signal` 唤醒至少一个等待该条件的线程
`pthread_cond_broadcast` 唤醒所有等待该条件的线程

**自旋锁**
自旋锁适用场景：锁被持有的时间非常短，且线程不希望承担线程调度的成本。自旋锁通常作为实现其他类型锁的底层原语（你大多时候都不需要使用它）。
在用户态，自旋锁通常没那么有用，除非你在编写不允许抢占的实时程序。
不要在持有自旋锁的情况下调用任何会休眠的函数

**屏障**
屏障允许每个线程等待所有协作线程到达同一个点，然后从该点继续执行。
屏障允许任意数量的线程等待，直到所有线程都完成了处理，但这些线程不必退出。在所有线程到达屏障后，他们可以继续工作。
## 线程控制
### 线程属性
detachstate 属性允许线程一开始就是分离的（相当于pthread_detach）
guardsize 属性：在线程栈末尾添加哨兵，一旦线程栈溢出到警戒区，应用程序会收到错误、以及信号
### 同步属性
递归互斥锁：一般用起来比较棘手，除非没有其他可行方案，否则不考虑使用它
flockfile、ftrylockfile: 获取给定 FILE 对象的锁，这个锁是递归的，持有该锁时可以重复获取，不会引起死锁
### 线程特定数据
原因：
1. 为每个线程维护一份数据
2. 便于基于进程的接口适配多线程场景

### 取消选项
pthread_cancel 不会等待线程终止，线程收到取消请求后会继续执行，直到遇到取消点（大部分系统函数中）

### 线程和信号
pthread_kill 发送信号给线程

### 线程和fork
父进程调用fork 创建子进程后，子进程中只有一个线程。父进程的线程如果持有任何锁，这些锁在子进程中也是锁定状态。但子进程不知道这些锁的状态，也没法解锁。
子进程调用 exec 可以规避该问题（原来的资源都不用管了），标准要求在fork 到 exec 中间，子进程只能调用信号异步安全的函数
pthread_atfork 目的是解决fork 后锁的问题，但它存在缺陷，仅有有限场景可用

pread 并发读
pwrite 并发写
