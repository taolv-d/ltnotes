本书主要介绍了UNIX（POSIX.1, SUS 等）的系统函数，穿插讲解了这些系统函数为什么要这样设计，有些会给出实现代码。
UNIX 如今已经不是任何一个具体的操作系统了。他变成一个商标，由The Open Group持有^[https://www.opengroup.org/] 。
UNIX 标准化为了让应用程序在不同的操作系统之间方便的移植：
**单一 UNIX 规范（Single UNIX Specification）**：规定了操作系统必须提供哪些系统接口、命令、工具和联网服务。
**POSIX** 标准：侧重于可移植操作系统接口本身。
一个操作系统实现UNIX的规范，并取得 The Open Group 的认证，就可以称为Unix 系统，例如Mac OS。也有一些操作系统会兼容UNIX 规范，但没有商标（没有认证，或者接口不完全一致），例如FreeBSD、Linux。
可以看到这本UNIX与C的关系非常密切，这也是C一直经久不衰的原因之一

# UNIX 系统
## 限制（2.5）
UNIX 实现中有很多不同的限制，如文件名最大长度、进程可以打开的文件数量、最大进程数等等。标准没有把这些限制统一，原因是：1. 早期UNIX 变体较多，无法完全兼容。2. 很多限制跟硬件相关，强行限制反而不好。
因此在编写可移植的程序的时候需要考虑这些限制。通常：
1. 在编译时，头文件的宏中定义
2. 对于文件或目录**无关**的，调用 sysconf 函数判断
3. 对于文件或目录**有关**的，调用pathconf, fpathconf函数判断

### 系统文件和信息
UNIX 中有很多系统自己的文件，例如 shadow 文件（存储密码，只有少数程序需要访问）
UNIX 的数据文件通常要有三个函数：
- get 函数：读取一条记录
- set 函数：打开文件、倒回文件（到开头）
- end 函数：关闭文件

# 文件与IO
## 文件IO
UNIX shell 三个默认文件描述符：
- 0 标准输入
- 1 标准输出
- 2 标准错误输出

**工作目录**：同一进程内的所有线程共享当前的工作目录
**空洞文件**：通过 lseek 调整文件偏移量时，偏移量可以大于当前文件的长度，此时文件出现空洞，空洞内都是0，但是不占用磁盘空间。（但是一些操作，例如读取文件再写入到一个新文件中，空洞就会被真实的0填充，此时就会占用空间）
**预读**：操作系统一般采用预读策略，检测到应用程序正在进行顺序读取时，会多读取比要求更多的数据
### 打开文件的内核数据结构
下图是两个进程打开同一个文件时，内核中的数据结构。
1. 每个进程都有一个表，记录文件描述符，根据文件描述符可以对应到文件表项
2. 文件表项纪录：
	1. 文件状态标志：只读、读写、追加、只写等
	2. 当前文件的偏移量
	3. 指向该文件的 v 节点指针
3. 文件的v节点结构体（每个文件一个）
多个进程操作同一问价时，如果不是原子操作，就会有竞争风险

### 原子操作
pread 相当于先调用lseek，再调用 read。pwrite 类似：
- 调用 pread 时，无法中断其定位和读取操作
- 调用 pread 时，当前文件偏移量不更新
### sync
我们向文件写入数据时，内核先将数据复制到缓冲区，随后数据进入队列，最后写入文件。
sync 将所有修改过的块缓冲区排入队列，然后返回，他不等待实际的写磁盘完成
### ioctl
ioctl 是文件操作的IO操作的杂货箱，在驱动程序中用的比较多
### /dev/fd
打开文件 `/dev/fd/n`等价于复制文件描述符`n`
## 文件和目录
**stat** 函数通常是 `ls -l` 命令使用
**文件类型**：
1. 普通文件
2. 目录文件，只有内核可以直接写入目录文件
3. 块特殊文件（磁盘驱动器）
4. 字符特殊文件
5. FIFO
6. 套接字
7. 符号链接
**目录文件权限**：
- 读权限：获取目录中的文件名列表
- 执行权限：访问该目录（搜索）
**粘着位**：应用程序终止时，正文部分的一个副本仍保留在交换区，方便后续再次快速启动该程序
### 文件系统
- i 结点包含了与文件有关的所有信息：文件类型、文件访问权限位、文件长度、指向文件数据块的指针。stat 函数的大多数信息是从i 节点获取中的。不过，文件名跟i 结点号存储在目录项中
- 一个目录项中的i 结点只能指向**同一文件系统**的i 结点，不能跨操作系统
![[attachments/Pasted image 20261115164849.png]]
### 链接 link
很多操作系统不允许出现指向目录的硬连接（或者只有root 权限才行），目的是避免循环
**ulink**
- 每个文件都有链接的计数。当关闭文件时，内核检查打开该文件的进程数，如果为0，内核再检查文件的链接数，如果也为0，则删除文件。
- 利用上面ulink的特性，进程中的临时文件可以创建后马上调用ulink。这样进程结束（崩溃），临时文件就会自动删除
- ulink 权限，必须要对包含该文件的目录有读写和执行权限，同时还要满足下列三个条件之一：
	- 拥有该文件
	- 拥有该目录
	- 具有超级用户权限

### 符号链接
符号链接会在文件系统中引起循环，要避免
### 工作目录
每个程序运行在独立的进程中，shell 的当前工作目录并不会随着程序调用chdir 改变
## 标准IO库
UNIX 中标准IO库一般调用系统IO函数实现
### FILE
应用程序应该一直不需要检查FILE对象
### 缓冲
三种缓冲类型：
- 全缓冲
- 行缓冲
- 不带缓冲（标准错误输出）

setbuf 函数可以改变缓冲类型，将buf 设为NULL 则关闭缓冲
应该让操作系统选择缓冲区的长度并自动分配缓冲区。有些缓冲区实现包好额外信息
fflush 函数将流中所有未写的数据传送至内核
### 读流和写流
getc可实现为宏，fgetc 不可实现为宏
putc可实现为宏，fputc 不可实现为宏。putchar(c) 等同于putc(c, stdout)
### 二进制IO
一个系统的数据在另一个系统读取的问题：
1. 对齐不同，通常采用紧密对齐
2. 不同操作系统存储整形、浮点型的二进制格式也有不同

# 进程
## 进程环境
### main 函数
内核执行C程序之前，会在main 函数之前调用一个启动例程，可执行文件将启动例程作为程序的启始地址，这一操作由链接器设置，链接器由编译器触发。启动例程从内核获取命令行参数和环境变量，随后调用main 函数。
main 函数返回，exit 函数自动调用。启动例程如下：
```C
exit(main(argc, argv))
```
### 进程终止
8种终止方式（前5种正常退出，后3种异常退出）：
1. main 返回
2. 调用exit函数：执行特定清理再返回内核
3. 调用_exit 或_Exit函数：立即返回内核
4. 从最后一个线程启动例程返回
5. 从最后一个线程调用 pthread_exit 函数
6. 调用abort函数
7. 接收一个信号
8. 最后一个线程对取消请求做出响应

退出状态：
- main函数隐式返回（不执行return），退出状态为0
- 未定义的退出状态
	1. 调用三个 exit 函数未指定退出状态
	2. main 函数调用return，但是没指定返回值
	3. main 函数的定义没有指定返回值为 int

**atexit 函数** 用于注册 exit 函数自动调用的函数（exit handler），ISO C 规定最少可以注册32个函数。
- 注册的函数以函数指针形式传入，参数类型跟返回值均为 void。
- 这些函数调用的顺序与注册的顺序相反（栈结构）
如下图所示，内核执行一个程序的**唯一**方法是调用exec，进程**自愿**终止的唯一方式是显示或隐式调用_exit 或_Exit 函数

### 命令行参数与环境变量
ISO C 跟POSIX 规定 `argv[argc]`为空指针，因此下面的写法是合法的：
```C
for(i=0; argv[i] != NULL; i++)
```

每个程序都会接收到一个环境列表，保存到全局环境变量`environ`
访问特定环境变量通常使用 `getevn` 和 `putenv` 函数
### C 程序的内存布局
一个C程序由以下几部分组成：
- 正文段：CPU 执行的机器指令，正文段通常可共享
- 初始化的数据段：也叫数据段，包含程序中已经显示初始化的变量
- 未初始化的数据段：也叫bss 段（名称来源于早期汇编操作符“block start by synbol”），这部分的数据回被内核在程序执行前初始化为0或空指针
- 栈：每次递归函数调用自身，就使用一个新的栈帧
- 堆

上面5部分只有 **正文段跟初始化数据段** 回保存到程序文件中
程序文件中还会有：符号表、调试信息、作用域动态共享库的链接表等，这些不会装载到程序的映像中。

### 内存申请
ISO C 的三个内存申请函数：
- malloc，不初始化
- calloc，申请到的内存的每个比特都会初始化为0
- realloc，增加或缩小之前申请的内存区域。可能回移动内存（指针数值变化），新增区域的初始值不确定。

sbrk 系统调用：可以扩大或缩小进程的存储空间。但大多数malloc 和 free 的实现都不缩小进程的存储空间。释放的空间会保留为进程空间以备稍后再次被分配，这些空间保存在malloc 池中，不会返回给内核。
大多数实现分配的内存比请求的稍大一些，额外的空间用来记录管理信息：如块长度、指向下一个块的指针等。

其他内存函数：
alloca：在栈上分配内存

## 进程控制
### 进程标识符（PID）
每个进程用一个非负整数作为独一无二的进程ID。进程ID会被复用，UNIX 采用延迟复用算法，这样防止一个新进程被误认为是使用相同ID的某个已终止的进程
**特殊进行**
- 0：调度进程（swapper），他是内核的一部分，运行在内核态
- 1：init 进程，由内核在引导过程结束时调用。用不消亡，以超级用户权限运行在用户态，是所有孤儿进程的父进程
- 2：页守护进程（pagedaemon）,负责虚拟内存系统的分页机制
### fork 函数
fork 函数用于创建子进程，fork 函数调用一次，返回两次：
1. 子进程返回 0
2. 父进程返回 子进程的 PID，父进程创建多个子进程时，有PID可以区分（没有其他函数可以获取某个字函数的PID）

子进程跟父进程继续执行fork函数之后的命令，这里的代码一般这样的：
```C
pid_t pid;
if((pid=fork()) < 0){
	// error
} else if(pid == 0){
	// 子进程
} else {
	// 父进程
}
```

子进程获得父进程的数据段、堆、栈的副本（写时复制），此外还有很多，可以参考原书
**文件共享**：子进程跟父进程共享相同的文件描述符、**文件偏移量**，参考下图
![[attachments/Pasted image 20261115182616.png]]

**fork失败**：
1. 系统中有太多进程了
2. 某个用户的进程数量超过系统限制，该用户不能再创建

**fork 用途**：
1. 进程希望复制自己，让父子进程执行不同的代码，常见于网络服务器
2. 进程想要执行不同的程序，如shell

**vfork**：不可移植，不应该使用
