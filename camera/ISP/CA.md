CA 即色差，图像上表现为紫边
# 色差产生的原因
色差是镜头的像差之一，主要有两种表现^[https://zhuanlan.zhihu.com/p/151431106] ：

|          | 轴向色差                                                  | 横向色差                                                  |
| -------- | ----------------------------------------------------- | ----------------------------------------------------- |
| 原因       | 光轴上不同色光不能聚焦到同一点                                       | 镜头对不同色光的放大倍率不同                                        |
| 示意图      | ![[attachments/Pasted image 20260904234302.png\|338]] | ![[attachments/Pasted image 20260904234532.png\|257]] |
| 图像表现     | ![[attachments/Pasted image 20260904234607.png]]      | ![[attachments/Pasted image 20260904234616.png]]      |
| ISP 能否矫正 | 不能，随对焦距离变化                                            | 可以，根据放大倍率变化，缩放RGB三个通道                                 |
# 色差的标定
ISP 只能标定横向色差，即标定出 R G B 三个通道的缩放关系，然后ISP中缩放到同一的大小来避免色差。
镜头设计的时候也可以给出色差的补偿建议

标定可以用圆点图，或者棋盘格：
下图是拍摄的圆点图。如果分离RGB三通道，就可以看到三个通道中圆点稍微错位。计算出这个错位的偏移，就可以补偿色差。
![[attachments/Pasted image 20260904235724.png|387]]

不过，色差这个东西比较神奇，标定出来的效果不一定好。同时即便按光学补偿值来矫正，效果也不一定好。因此通常还是用golden参数。
# 色差检测域移除

ISP 主要实现的色差模块主要还是上面说的标定+分通道resize方案。但是很多紫边不能被矫正。例如下图这种过曝区域产生的紫边，由于RGB三通道已经开始饱和，通过resize 是没办法恢复的。
![[attachments/Pasted image 20260905165845.png|532]]

因此，一些ISP实现中，会专门的紫边移除功能，检测这种紫边并移除（降低饱和度变为灰色边缘）。

下面简单介绍一篇紫边矫正算法（粗略，不深入细节）：
文章：《Automatic detection and correction of purple fringing using the gradient information and desaturation》^[https://eurasip.org/Proceedings/Eusipco/Eusipco2008/papers/1569101556.pdf]
算法框图如下，主要就是紫边的检测，矫正两部分
![[attachments/Pasted image 20260905174913.png|524]]

**紫边区域检测**  
算法会同时检查图像中的每个像素，同时满足下面的条件才会被判定为紫边：
- **亮度条件**：NSR （Near-Saturated Regions）在高亮区找
- **找紫色区**（Candidate Regions）像素的色度值落在一个预先在**CIE xy色度图**中定义的“紫色”范围内。
- **边缘条件**：该像素位于图像中颜色或亮度**剧烈变化的边缘**（用梯度信息衡量），因为紫边正是由镜头色差或传感器溢出（Blooming）等问题在高反差边缘产生的。

**紫边区域修复**  
对于被检测为紫边的像素，算法在CIE xy色度图中对其进行**颜色去饱和度**处理。简单来说，就是削弱该区域紫色成分的饱和度，使其颜色变得更淡、更接近中性灰，从而自然地融入周围环境，达到视觉上消除紫边的效果

**优缺点**
本文的算法比较简单，运算容易硬化。但是鲁棒性一般，容易误杀真实的紫色边缘。
